Zone 67 — Secure Server & Backup Plan

The Ministry of Defence asked our team to secure the network, the infrastructure and the tools of Zone 67. This page explains how we install, configure and protect the enterprise server, and how an automatic backup plan keeps the data safe, even after a disaster.

The mission in one minute

The problem

Zone 67 runs on scattered machines, with no central accounts, no network separation and no tested backups. One fire, one ransomware attack or one stolen password could stop the site.

What we deliver

  • One hardened enterprise server
  • A segmented, filtered network
  • Secure remote access for admins
  • An automated backup + recovery plan

Our rules

  • Deny by default, allow by need
  • No single point of failure for data
  • Everything logged, everything documented
  • Follow ANSSI and CIS hardening guides
In plain words

Think of Zone 67 as a military base. The firewall is the main gate, the VLANs are separate buildings with badge doors, the bastion is the escorted visitor desk, and the backups are copies of the plans kept in several safes, one of them far away.

Say it

"Our goal is simple: if anything breaks, Zone 67 keeps working or comes back fast, and nobody gets in without permission."

Presented by · Team lead

The big picture

Everything goes through the firewall. Behind it, the core switch splits the site into four isolated zones (VLANs). The backups live in their own zone, which nobody can reach from the users' side. [2]

Why four zones?

If a user's PC gets infected, the virus stays in the users' building. It cannot walk into the management room or the backup vault, because the firewall does not open those doors.

Say it

"Every packet crosses the firewall. Each zone only talks to the zones it really needs."

Presented by · System engineer

The server: hardware, OS and services

One physical rack server runs a hypervisor, and the hypervisor runs several virtual machines. Each VM does one job, so a problem in one service does not take down the others.

In plain words

The server is one big building split into apartments (the VMs). The hypervisor is the building manager: it gives each apartment its own walls, water and electricity. RAID 1 means two disks write the same thing, so if one dies the other keeps going.

Say it

"We chose virtualisation because one VM per role is easier to secure, to back up and to restore."

Installation, step by step

  1. Rack and cableMount the server, plug both power supplies into the UPS, connect both 10 GbE links.
  2. Secure the firmwareUpdate BIOS and iDRAC, set a BIOS password, enable Secure Boot and TPM.
  3. Build the RAIDRAID 1 for the system, RAID 10 for VM data.
  4. Install Proxmox VEStatic IP in VLAN 10, repositories, updates, admin account with MFA.
  5. Configure the networkLACP bond, VLAN-aware bridge, one VLAN tag per VM.
  6. Create the VMsFrom hardened templates, with the resources shown above.
  7. Deploy Active DirectoryCreate the zone67.lan domain, DNS and DHCP, then add DC02.
  8. Deploy the servicesFile shares with rights per group, intranet, SIEM, bastion.
  9. Harden everythingApply ANSSI / CIS settings (see the Security section).
  10. Monitor and back upInstall Wazuh agents, schedule backup jobs, test a restore.

Remote access: four checkpoints

In plain words

A VLAN is a separate corridor in the same building. The VPN is a private tunnel through the public internet. The bastion is the security desk: you sign in, you are escorted, and the camera is recording.

Say it

"Admins never connect straight to a server. They pass four checkpoints, and every session is recorded."

Presented by · Cyber security expert

Security: defence in depth

No single protection is perfect, so we stack them. An attacker has to break every layer to reach the data, and each layer raises an alarm. [3]

Accounts & identity

  • Personal accounts only, no shared "admin"
  • Separate admin and daily accounts
  • MFA on VPN, bastion and Proxmox
  • LAPS: a unique local admin password per machine
  • Password policy: 14+ characters

Hardening

  • ANSSI and CIS benchmark settings
  • Unused services and ports disabled
  • SSH keys only, no root login
  • GPO: USB storage blocked, screen lock
  • Monthly patching window

Detection

  • Wazuh agent on every VM
  • All logs centralised in SIEM01
  • Alerts: failed logins, new admin, backup failure
  • Suricata IDS on the firewall
  • Logs kept 1 year
In plain words

The SIEM is the control room with all the camera screens. It collects every log from every machine and rings an alarm when something looks wrong, like 50 wrong passwords in one minute.

Say it

"We assume that one layer will fail one day. That is why we have six, and why every layer is watched."

The backup strategy

We follow the 3-2-1-1-0 rule, the current standard for protection against ransomware. Every backup job runs by itself; humans only check the reports and test restores. [1] [2]

3copies of the datathe live data + 2 backups (we keep 4)
2types of mediadisks (PBS) and LTO tape
1copy off-sitePBS #2 at another ministry site
1copy offlinetape in a safe, no network
0errorsverified every week, restore tested every month

Backup architecture

How often, and for how long

TierMachinesBackup frequencyRPO (max data lost)RTO (max downtime)
Tier 1 · criticalDC01 · DC02 · FS01every 4 h + nightly4 h4 h
Tier 2 · importantWEB01 · SIEM01 · BAST01nightly24 h8 h

Retention (how long we keep)

  • PBS #1: 7 daily, 4 weekly, 6 monthly
  • PBS #2: 7 daily, 4 weekly, 12 monthly
  • Tape: 12 monthly tapes + 5 yearly tapes

Tools

  • Proxmox Backup Server: incremental, deduplicated, encrypted
  • LTO-9 tape drive, driven by PBS tape jobs
  • Windows shadow copies on FS01 for quick file undo

Fully automated

  • Scheduled jobs, prune and garbage collection
  • Weekly verify of every chunk
  • Email + Wazuh alert if a job fails
  • Only manual task: monthly restore test and tape swap
In plain words

Keep your house keys in three places: in your pocket, in a drawer at home, and at a friend's place in another city. Now lock one copy in a safe with no door to the street. Even a burglar with all your keys at home cannot reach that one.

Say it

"A backup that has never been restored is only a hope. We test a real restore every month."

Disaster recovery plan

Two numbers drive the whole plan. RPO is how much recent work we can afford to lose. RTO is how long the service can stay down. [4] [1]

Five scenarios, five answers

ScenarioWhat we doRTORPO
A disk diesRAID keeps running. Hot-swap the disk, the array rebuilds on its own.00
Someone deletes a fileRestore the file from shadow copies or from PBS file-level restore.15 min≤ 4 h
The server diesRestore the VMs from PBS #1 onto the spare host, tier 1 first.4 h≤ 4 h
RansomwareIsolate the network, find the last clean restore point, rebuild from PBS. If PBS is touched, restore from tape.24 h≤ 4 h (PBS) · ≤ 7 days (tape)
Fire or floodRestart the critical VMs at the off-site DR site from PBS #2.48 h≤ 24 h

When disaster strikes

  1. DetectAn alert from Wazuh, PBS or a user report.
  2. AssessWhat is hit, since when, is it spreading?
  3. DeclareThe team lead triggers the plan and informs the ministry.
  4. ContainIsolate the infected zone before restoring anything.
  5. RestoreTier 1 first (AD, files), then tier 2.
  6. Verify & reviewUsers test, then we write a report and improve the plan.
In plain words

A disaster recovery plan is a fire drill for computers. Everybody knows their role before the fire, so nobody panics during it. We rehearse it twice a year.

Say it

"For each scenario, we know what to do, who does it, and how long it takes."

Documentary research

Sources that justify our choices

Four reliable English sources: two official government guides, one U.S. standard and one industry survey. The small tags like [1] across the page show where each source supports a choice.

[1]

#StopRansomware Guide

★ Main source for the oral
Reference
CISA, FBI, NSA & MS-ISAC (U.S. government), updated September 2023. https://www.cisa.gov/stopransomware/ransomware-guide
Key idea
“Maintain offline, encrypted backups of critical data, and regularly test the availability and integrity of backups in a disaster recovery scenario.”
In our own words
Ransomware looks for backups it can reach and destroys them. So at least one copy must be unplugged, all copies must be encrypted, and a backup only counts if you have tested the restore.
Why it is relevant
Written jointly by U.S. cyber and intelligence agencies, so it is an official reference. It directly justifies our offline LTO tape, the AES-256 encryption in PBS and our monthly restore test.

2023 Ransomware Trends Report

★ Main source for the oral
Reference
Veeam Software, press release of 23 May 2023, survey of 1,200 organisations hit by ransomware. https://www.businesswire.com/news/home/20230523005553/en
Key idea
“Attackers almost always (93%+) target backups during cyber-attacks”, and 75% of victims lost at least some of their backup repositories.
In our own words
In almost every attack, the criminals go after the backups first, because without backups the victim is forced to pay. Three victims out of four lost part of their backups.
Why it is relevant
It gives real numbers that show why the backup zone must be isolated (VLAN 40, one port only) and why we keep a copy with no network. It is a vendor survey, so we use it for the trend and check it against the CISA guide.

Recommendations to secure administration of IT systems

Reference
ANSSI (French National Cybersecurity Agency), guide ANSSI-PA-022-EN, English version, 2018. https://cyber.gouv.fr/en/publications/recommendations-secure-administration-it-systems
Key idea
The guide sets “security objectives and the principles for developing a secure technical architecture for administration”.
In our own words
Administrator accounts are the keys to everything, so admin work must happen in a separate, protected zone, through controlled entry points, with strong authentication.
Why it is relevant
ANSSI is the French government agency that advises state administrations, including the Ministry of Defence, our client. It justifies our management VLAN, the bastion and MFA for admins.

SP 800-34 Rev. 1 — Contingency Planning Guide for Federal Information Systems

Reference
NIST (U.S. National Institute of Standards and Technology), 2010. https://nvlpubs.nist.gov/nistpubs/legacy/sp/nistspecialpublication800-34r1.pdf
Key idea
Defines the Recovery Time Objective (RTO) and the Recovery Point Objective (RPO) as the targets that drive a recovery plan.

It is the international reference for disaster recovery planning. Our tiers, backup frequencies and the RPO/RTO timeline follow its method.

Glossary

Useful for the audience, and for the questions at the end.

Hypervisor
Software that runs several virtual machines on one physical server.
VM (virtual machine)
A complete computer simulated in software.
Active Directory (AD)
Microsoft's central directory of users, computers and permissions.
RAID
Several disks working as one, so a single disk failure loses nothing.
VLAN
A virtual network that isolates groups of machines on the same switch.
Firewall
The device that allows or blocks traffic between networks.
VPN
An encrypted tunnel across the internet.
MFA
Multi-factor authentication: a password plus a second proof, like a phone code.
Bastion
The single, monitored entry point for administrators.
SIEM
A system that collects all logs and raises security alerts.
Hardening
Removing everything unnecessary and locking down settings.
PBS
Proxmox Backup Server: the backup software and storage.
Deduplication
Storing identical blocks of data only once, to save space.
Air gap
A copy with no network connection at all.
RPO
Recovery Point Objective: maximum data we accept to lose.
RTO
Recovery Time Objective: maximum time the service can be down.
